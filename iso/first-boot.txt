
Thermite is installed; configure this machine as its owner.

No private house, service account, credentials or runtime services exist yet.
Log in as the owner account you chose in the OS installer and connect to the
Internet: installation downloads host packages, container images and
integrity-pinned runtime files.

On the Ubuntu image, first make sure the prerequisites are present (nothing
changes when they already are):

  sudo apt-get update && sudo apt-get install python3-venv git

Create your private site:

  thermite init "$HOME/thermite-site"
  cd "$HOME/thermite-site"

Edit instance/devices.yaml and instance/host.yaml for your equipment and
time zone. The generated inventory is fictional; replace it before
commissioning real equipment. Then validate and commit the site:

  thermite check --config "$HOME/thermite-site"
  git init --initial-branch=main
  git add .
  git commit -m 'Initialize private Thermite site'

Deploy the complete site with one approval. Install creates the non-login
thermite service account (UID/GID 9001), starts the native services and the
HTTPS gateway, and provisions internal runtime access itself:

  thermite install --config "$HOME/thermite-site" --dry-run
  thermite install --config "$HOME/thermite-site"

Installation switches ~/.local/bin/thermite to the application it verified.
Log out and back in afterwards: the new login puts ~/.local/bin first on
PATH, so thermite runs that application, and applies your new thermite group
membership. Installation prints the HTTPS URL and the
certificate authority file each browser or terminal client must trust once.
Inspect the result with:

  thermite status --config "$HOME/thermite-site"
  thermite health --config "$HOME/thermite-site" --production

Update later with thermite upgrade --config "$HOME/thermite-site". Keep the
site repository private. The full guide is docs/installation.md under
/opt/thermite/venv/lib/python*/site-packages/thermite_app/runtime/.
