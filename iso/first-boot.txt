
Thermite is installed. This guide is /opt/thermite/FIRST-BOOT.txt.

On the Arch image, the first boot sets Thermite up by itself: as the owner
you chose in the installer, it creates an empty house in ~/thermite-site,
commits it, and runs thermite install --yes, which creates the non-login
thermite service account (UID/GID 9001), starts the native services and the
HTTPS gateway, and provisions internal runtime access. It needs the Internet
for host packages, container images and integrity-pinned runtime files.
While it runs, sudo runs any command as root for the owner without a
password; that rule is removed when it ends, and at the next boot if the
power fails first. Your login shows its progress until it is done:

  journalctl -fu thermite-first-boot.service
  less /var/log/thermite-install/first-boot.log

Then log out and back in: the new login puts ~/.local/bin first on PATH, so
thermite runs the application install verified, and applies your new
thermite group membership. Install prints the HTTPS URL and the certificate
authority file each browser or terminal client must trust once. Inspect the
result with:

  thermite status --config "$HOME/thermite-site"
  thermite health --config "$HOME/thermite-site" --production

The house starts empty. Add your rooms and equipment to
instance/devices.yaml, check and commit them, and deploy again:

  cd "$HOME/thermite-site"
  thermite check --config "$HOME/thermite-site"
  git commit -am 'Add the house'
  thermite install --config "$HOME/thermite-site"

If the first boot did not finish (the login says why), start it again with
sudo systemctl start thermite-first-boot.service. It keeps the house it
made; if the stopped run left an install open, it first finishes or rolls
back that install, then installs again. Or do its steps by hand as below.
The installer's answers, receipt and logs are kept in
/var/log/thermite-install.

Without the image's key, SSH accepts your password. Once your key logs in
(ssh-copy-id from your machine, then ssh -o PasswordAuthentication=no to
check), turn passwords off, keeping this session open until a new key login
works:

  printf 'PasswordAuthentication no\nKbdInteractiveAuthentication no\n' |
    sudo tee /etc/ssh/sshd_config.d/30-thermite-keys-only.conf
  sudo sshd -t && sudo systemctl reload sshd.service

By hand, and on the Ubuntu image: connect to the Internet, then on Ubuntu
make sure the prerequisites are present (nothing changes when they already
are):

  sudo apt-get update && sudo apt-get install python3-venv git

Create your private site. --empty starts with no rooms or devices; without
it the site holds a fictional example house to replace before commissioning
real equipment. Edit instance/host.yaml for your time zone:

  thermite init --empty "$HOME/thermite-site"
  cd "$HOME/thermite-site"
  thermite check --config "$HOME/thermite-site"
  git init --initial-branch=main
  git config user.name "$USER"
  git config user.email "$USER@$(uname -n).local"
  git add .
  git commit -m 'Initialize private Thermite site'

Deploy the complete site with one approval:

  thermite install --config "$HOME/thermite-site" --dry-run
  thermite install --config "$HOME/thermite-site"

If install says it finished or rolled back an earlier install and stopped,
run it once more.

Update later with thermite upgrade --config "$HOME/thermite-site". Keep the
site repository private. The full guide is docs/installation.md under
/opt/thermite/venv/lib/python*/site-packages/thermite_app/runtime/.
