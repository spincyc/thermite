Get started

thermite runs on a Linux machine on your home network. Choose where it will live, or try the fictional example first. These are development builds, version 0.1.0.dev0.

Choose where to run it

Your setupInstallation path
Stock Arch Linux, or an existing Ubuntu ServerInstall thermite on your server. Keep your existing operating system and create a private site.
A dedicated machineBuild the standalone ISO. Arch is the default base; Ubuntu is optional. Boot it to install the operating system and thermite on that machine.

Review the system requirements and network ports before installing. Administer Thermite with your own login; application services use a separate service account.

Try the example

You can generate configuration and use the terminal remote in demo mode before connecting hardware. On stock Arch, prepare the development tools:

sudo pacman -Syu --needed python python-pip git nodejs npm

On Ubuntu Server, use sudo apt-get update followed by sudo apt-get install python3-venv git nodejs npm instead. From a reviewed source checkout, create a separate application environment:

python3 -m venv ~/.venvs/thermite
~/.venvs/thermite/bin/python -m pip install .
. ~/.venvs/thermite/bin/activate
thermite init ~/my-thermite-site
cd ~/my-thermite-site
thermite generate
thermite validate
thermite remote --mock

The initial inventory is fictional. Generating and validating files sends no device commands; the mock remote simulates controls. Its first run downloads its locked terminal dependency with npm. Podman is needed when you move on to an openHAB test runtime or server installation.

The application stays in its Python environment. init creates a separate private site; it starts no services and creates no Git repository.

Describe your house

Edit instance/devices.yaml and instance/host.yaml in the private site. Replace the example inventory with your own rooms and devices, using fixed network addresses. A TV entry looks like this:

rooms:
  living_room: {label: Living Room}

devices:
  - id: living_room_tv
    room: living_room
    kind: tv
    make: Sony
    model: Example TV
    name: Living Room TV
    ip: 192.0.2.20
    controls:
      observe: [sony_rest]
      control: [sony_ip_control]

observe lists interfaces thermite may read. control lists interfaces it may command. The sample address above is reserved for documentation; use the TV's actual address in your private site.

Create a private Git repository for that site. Commit real inventory, host settings, native version pins and thermite-site.json. Generated conf/, metrics/ and deploy/, credentials and runtime state stay outside Git. The public application repository should contain only fictional examples.

Check and deploy

After editing the house file:

thermite generate
thermite validate
thermite test boot

The boot check loads the generated configuration in an isolated openHAB runtime and reports what loads. Follow the server installation guide to prepare the host, commit your private site and deploy it. thermite install --dry-run shows the planned installation steps. thermite status reports the running services and their addresses.

Connect and use it

The installation guide covers site access and the first account. After commissioning authenticated access, open your site's web address and sign in. In a terminal:

thermite access login --url https://thermite.example:13600 --user admin
thermite remote --url https://thermite.example:13600

Use --ca-file at login for a private certificate authority. Choose a room and source in Remotes; use Pair devices for equipment that needs an on-screen code. Cameras and Site show cameras and connections. Security remains Not connected until an alarm integration is configured.

Keep it running

  • thermite health --production reports device health.
  • thermite history lists deployments; thermite rollback restores the previous one.
  • thermite version shows application and runtime versions.
  • Application releases and private sites explains application upgrades and cached releases for rollback.
  • thermite help <command> explains any command, with examples.
