Thermite listening ports

Thermite's default TCP listeners occupy 13600–13625, anchored at the HTTPS application on 13600. lib/oh_ports.py owns the allocation. instance/host.yaml keeps the site's native HTTP/HTTPS choices and optional metrics: <service>_port overrides. Generation rejects invalid values and collisions, including collisions with the sandbox, boot test and docs preview. Explicit overrides may leave the default range. Commit changes and run thermite install --config DIR or thermite upgrade --config DIR; the same workflow updates the native boundary and gateway together. Gateway and callback listeners are checked against the complete allocation and native upstream.

HTTPS is the application entry point whether authentication is on or off. Installation restricts native HTTP/HTTPS to loopback and blocks non-loopback traffic to native HTTP, HTTPS, Karaf, LSP and shutdown ports in the dedicated inet thermite_native nftables table. It leaves other firewall tables intact, verifies the active policy and reapplies it before every native runtime start. An unknown existing table or modified policy requires review before replacement. For Sonos, the workflow derives exact callback routes from committed identities and live device descriptions; existing verified routes and ports are retained. The relay accepts only the verified NOTIFY traffic, never general native API access.

The installer and upgrade configure the stopped native console in userdata/etc/org.apache.karaf.shell.cfg, preserving other settings and fixing its address to loopback. Generated conf/services/runtime.cfg sets org.openhab.lsp:port=13604. Sandboxes retain their LSP bundle blacklist. The native language server's lack of an address setting is visible in the pinned openHAB 5.2.3 source. The console's independent setting is documented by its pinned distribution configuration.

Karaf also opens a separate shutdown-control socket. Thermite sets its port and loopback address in each instance's userdata/etc/custom.properties, preserving the upstream stop command instead of accepting a random listener. Native, sandbox and boot-check instances use distinct ports so they can coexist. The behavior is defined by the pinned Karaf shutdown setup and stop command.

The default migration moves native HTTP/HTTPS from 8080/8443, Karaf from 8101, LSP from 5007, the helper from 8099, Prometheus from 9090, node_exporter from 9100, blackbox_exporter from 9115, the exporter from 9480, Grafana from 3000, Alertmanager from 9093, ntfy from 2586, notifications from 9481, authenticated access from 9443, sandbox HTTP/HTTPS/console from 18080/18443/18101, boot-check HTTP/HTTPS/console from 18081/18444/18102, and the docs preview from 8000. Regenerate the private site, review generated units, run the unified install/upgrade, and update bookmarks as needed. Existing runtime state is not rewritten by generate alone.

Why this range

Checked on 2026-11-02: the IANA Service Name and Transport Protocol Port Number Registry has no service assignment for 13401–13719. The chosen run avoids registered service ports, the usual application defaults displaced above, and Kubernetes' default 30000–32767 NodePort range. 13000 was considered but already has open-source users, including Prysm's QUIC listener and the AgentTeams dashboard. Targeted searches found no known open-source default allocation for the chosen 13600–13625 run. This is a local convention, not an IANA reservation or a promise that no other program uses those numbers. Startup preconditions still check whether required ports are occupied.

Device destinations keep their protocol ports: receiver HTTP 8080, Sonos 1400, Google TV 6466/6467, Cast 8009, matrix telnet 23 and other device protocols do not move. Discovery multicast/broadcast ports (including mDNS, SSDP and vendor discovery), dynamically negotiated device/media sockets and test fixture servers bound to port 0 remain protocol or operating-system allocations.
